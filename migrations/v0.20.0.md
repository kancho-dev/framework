# v0.20.0 — Memory Service Retirement, Role Selection From The Next Action, And `/no-context`

This release removes the optional memory service and its `memory-search` skill, makes `FRAMEWORK.md` resolve role selection for task sessions, gives the task-browser metadata CLI its own reference file, adds an optional `/no-context` command template for bounded work that should not load framework context, and promotes the optional Tokens / Cost Analyzer.

Most framework-side changes need no workspace action; they live entirely inside `framework/`, which an update replaces wholesale. The removal below is the exception: it withdraws an optional component, so workspaces that used it must decide what to do before and after updating.

## Breaking changes

**The optional memory service and the `memory-search` skill are removed.**

- `memory-service/` (CLI, PostgreSQL runtime, schema migrations, session adapters, setup scripts, and its documentation) is deleted from the framework source.
- `SKILLS/memory-search/` and its `SKILLS/INDEX.md` row are deleted. The `mem` command is no longer a framework-supported capability.
- Framework guidance no longer routes any run to searchable memory. Curated Markdown remains the source of truth, as it already was.

This affects only workspaces that installed and used the optional service. Core task, role, review, and state workflows do not depend on it and are unchanged.

### What the update does not do

Updating framework source is a source-tree operation only. It does **not** drop PostgreSQL databases or schemas, remove Docker containers or volumes, delete your ignored `memory-service/.env` or `node_modules/`, touch imported sessions or their original sources, remove shell aliases or global `npm link` registrations, or export anything on your behalf. No automated export or deletion is provided.

### Required checks if you used the memory service

1. Stop relying on the framework-managed `mem` command before updating. It disappears with this release.
2. If you need continued access to the implementation or to your records, do this **before** updating: keep a checkout of tag `v0.19.0` (the last release containing the service), or export what you need using your existing installation. The source stays recoverable from Git history but is unsupported from v0.20.0 onward.
3. After updating, remove your own local state — aliases, global links, databases, schemas, containers, volumes, credentials, and ignored files — deliberately, through your own reviewed cleanup. The framework will not do it and cannot see it.
4. Remove workspace-local references to `memory-search`, the `mem` CLI, or `framework/memory-service/` from custom skills, command prompts, and workspace docs.

## Required checks

1. If optional native command prompts are **symlinked selectively**, add a symlink for `framework/prompts/no-context.md` when the `/no-context` command should be available locally. A per-file symlink loop does not pick up prompts added by later releases.
2. If optional native command prompts were **copied** instead of symlinked, re-copy `framework/prompts/` when the Operator wants `/no-context` available. Copies never auto-update.
3. If neither applies, no action is needed; the workspace simply has no `/no-context` command.

## Optional checks

4. `/no-context` instructs a run to read no framework files, select no role, and write no framework-managed state. Confirm this is acceptable for the workspace before installing it. It governs agent behavior, not tool autoload: a tool that always loads `AGENTS.md` or `CLAUDE.md` will still have loaded them.
5. Task-browser metadata CLI documentation moved from `tools/task-browser/README.md` into `tools/task-browser/METADATA-CLI.md`. The README keeps a pointer, so existing references still resolve. Update workspace-local docs or custom skills that cite the old location only if a direct link is preferred.
6. The Tokens / Cost Analyzer is now documented as an optional alpha tool. Its standalone `npm start` path needs no workspace config. To expose it through Cockpit, explicitly set `tools["tokens-cost-analyzer"]` to `true` for each selected workspace in `.tools-config/tool-orchestrator/workspaces.json` (or the file named by `TOOL_ORCHESTRATOR_WORKSPACES_CONFIG`). Keep generated analyzer reports and local pricing/subscription state under the ignored `.tools-config/tokens-cost-analyzer/` path.

## Not required

- No change to the workspace `AGENTS.md`. The v0.18.0 boundary still applies; if it was merged then, nothing further is needed now.
- No task, project, state, or metadata migration.
- No action for the `FRAMEWORK.md` read-order and role-selection changes. They are inherited with the framework update.
- Workspaces that use no command templates and that never installed the optional memory service need do nothing for this release.
